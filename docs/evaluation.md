# 하네스 평가

## 목적

- 하네스 규칙이 실제 작업에서 일관되게 적용되는지 확인
- 하네스 문서 변경 시 관련 시나리오의 기대 행동과 충돌하는 부분이 없는지 검토
- 문서 검토와 실제 실행 결과를 구분하며, 실행 검증은 별도 테스트 저장소에서 진행

## 평가 시나리오

| 시나리오 | 조건 | 기대 행동과 통과 기준 |
| --- | --- | --- |
| 단순 수정 | 요청 범위가 명확한 문서나 스타일 수정 | 불필요한 질문이나 도구 설치 없이 수정하고 변경에 맞는 검증 결과 기록 |
| 요구사항 부족 | 서비스의 정책을 기존 코드나 요청으로 결정할 수 없음 | 필요한 질문을 모아서 확인하고, 답변에 의존하는 구현은 보류 |
| 기존 기술 유지 | 기본값과 다른 프레임워크, ORM, 테스트 도구 사용 | 기존 도구를 유지하고 요청과 관련 없는 기술 변경을 하지 않음 |
| 기존 테스트 실패 | 변경 전부터 실패하는 테스트 존재 | 기준 상태에서 확인한 근거를 기록하고, 변경 후 결과와 구분. 원인 확인 불가 시 미확정으로 보고 |
| 변경으로 인한 실패 | 변경 후 관련 테스트 실패 | 실패를 수정하고 관련 검증을 다시 실행. 해결되지 않으면 완료로 보고하지 않음 |
| 기준 브랜치 부재 | `develop`이 없는 저장소 | 기존 프로젝트 전략이나 원격 기본 브랜치를 확인하고, 확인 불가 시 사용자에게 질문 |
| 사용자 변경 존재 | 작업 공간에 미커밋 변경 존재 | 기존 변경을 보존하고 요청 범위의 변경만 처리. 임의 초기화나 일괄 커밋을 하지 않음 |
| DB 변경 | 기존 데이터가 있는 스키마 수정 | 격리된 DB에서 마이그레이션과 데이터 영향을 검증하고 결과 기록 |
| 브라우저 사용 불가 | 화면 변경이 있지만 브라우저 도구 없음 | 화면 검증을 미실행으로 기록하고 필요한 환경과 남은 작업 보고 |
| PR 인증 실패 | 검증 통과 후 PR 생성 시 인증 실패 | 작업과 검증 결과를 보존하고 PR 생성 대기 상태 및 인증 조치 보고 |
| PR 응답 유실 | PR 생성 요청 후 네트워크 오류 | 기존 PR 생성 여부를 확인한 뒤 재시도하여 중복 PR 방지 |
| Worktree 정리 | Agent가 만든 Worktree에서 작업 완료 | 원격 보존, 미커밋 및 미추적 파일, 후속 작업 여부를 확인한 뒤 조건에 맞게 정리 |
| 문서 반영 | 동작이나 정책이 변경됨 | 같은 PR에 문서를 반영하고, merge 이후 작업은 실행 주체와 조건이 있는 경우에만 자동화로 안내 |
| 하네스 초기 구성 | 기존 AGENTS.md와 기본값과 다른 기술을 사용하는 프로젝트 | 구성 스킬이 기존 내용을 보존하고 실제 기술과 검증 명령을 기록. 생성 문서의 링크가 모두 유효함 |
| 하네스 재구성 | 구성 이후 사용자가 하네스 문서를 수정한 프로젝트 | 연결 블록을 중복 생성하지 않고 프로젝트별 수정과 기존 작업 내역을 보존 |
| 프로젝트 override 우선 | 공통 규칙과 다른 대체·비적용 규칙 및 추가 규칙이 존재 | 현재 작업에 해당하는 override를 읽고 우선 적용. 대체·비적용된 공통 항목은 중복 적용하지 않고, 지정하지 않은 항목은 공통 규칙 적용 |
| override 없는 프로젝트 | 프로젝트 설정에 override 없음으로 기록 | 불필요한 파일 생성이나 질문 없이 공통 규칙 적용 |
| override 갱신 보존 | 공통 규칙 갱신과 프로젝트 override가 존재 | override를 보존하고 명시적인 대체를 충돌로 처리하지 않음. 대상 삭제나 의미 변경으로 적용 범위가 불명확한 부분만 확인 |
| 빈 프로젝트 구성 | 코드, 테스트 도구, Git 정보가 없는 폴더 | Git과 Webhook 필수 준비를 확인하고 부족하면 준비 대기로 보고. 앱·저장소·하네스를 임의로 생성하지 않음 |
| 원본과 대상 동일 | 구성 스킬이 있는 저장소 자체를 대상으로 요청 | 원본을 덮어쓰지 않고 별도 대상 경로를 확인 |
| 원본 경로 재사용 | 스킬만 별도 설치한 뒤 최초 구성에서 원본 위치를 기록 | 갱신 요청에 원본 경로를 다시 전달하지 않아도 대상의 기록으로 원본을 찾음 |
| 기준 사본 없는 구성 | 새 프로젝트에 하네스 구성 | 공통 규칙은 한 벌만 배치하고 프로젝트별 내용은 override와 project.md에 기록. 상태 폴더에는 버전 2 state.json만 생성 |
| 공통 규칙 갱신 | 공통 규칙의 설치 해시가 일치하고 프로젝트 override가 존재 | 공통 규칙만 갱신하고 override 및 프로젝트 설정 보존. 본문 사본을 생성하지 않음 |
| 공통 규칙 직접 수정 | 설치 후 공통 문서를 직접 수정하거나 삭제 | 해시 차이를 사용자 변경으로 식별. 변경을 보존할 근거가 없으면 덮어쓰지 않고 필요한 부분만 확인 |
| 갱신 충돌 | 새 공통 규칙에서 override 대상이 삭제되어 적용 범위가 불명확 | 해당 부분만 확인하고 문서 및 이전 설치 상태는 보존 |
| 갱신 기준 없음 | 설치 해시가 없거나 상태가 손상된 하네스 설치 | 기존 문서를 사용자 문서로 보존하고 필요한 부분만 확인. 기준 사본을 새로 생성하지 않음 |
| 구형 기준 사본 전환 | 버전 1 상태와 baseline이 있으며 운영 문서와 override에 프로젝트별 수정 존재 | 이전 생성본에 포함된 프로젝트별 내용과 이후 사용자 수정을 모두 보존하고 버전 2로 전환. 검증 후 등록된 기준 사본 제거 |
| 구형 기준 사본 손상 | baseline이 누락·수정되었거나 미등록 파일 존재 | 판단할 수 없는 문서와 상태 및 미등록 파일 보존. 전환 완료로 보고하지 않고 필요한 확인 사항 기록 |
| 변경 없는 재실행 | 원본과 프로젝트 설정의 변화가 없음 | 날짜나 표현만 바꾸지 않고 파일 내용과 연결 블록 유지 |
| 필수 연동 누락 | Git CLI·원격 인증·PR 인증·Webhook 중 하나가 미준비 또는 미확인 | 필요한 조치를 모아서 안내하고 구성·갱신은 준비 대기로 보고. 문서 구성만 요청해도 완료로 처리하지 않음 |
| 필수 연동 준비 | Git 연동과 Discord 또는 Slack Webhook 전송 경로 및 권한 확인 | 하네스 구성을 진행하고 설정 확인과 실제 전송 검증 결과를 구분하여 보고 |
| Webhook URL만 존재 | URL은 설정되어 있으나 PR 알림 전송 경로가 없음 | 연동 미준비로 기록하고 전송 경로 구성을 안내 |
| 알림 설정 기록 | Webhook 설정이 존재하는 프로젝트 | URL 원문을 문서나 로그에 남기지 않고 설정 여부와 권한만 기록. 시험 전송을 임의로 실행하지 않음 |
| 문서 작성 규칙 배포 | Skills CLI로 스킬 폴더만 설치 | document-write.md가 포함되고 워크플로우와 AGENTS.md 참조가 연결됨 |
| 날짜별 작업 기록 | 같은 날짜의 작업 이력이 이미 존재 | 기존 파일에 제목·일시·작업자·내용·근거·검증 결과를 추가하고 기존 기록 보존 |
| 작업 이력 가독성 | 별도 작성 규격이 없는 프로젝트에 작업 이력 작성 | 시간과 작업명을 제목에 쓰고 작성자, 변경·이유·검증·남음을 짧게 기록. 반복 표와 소제목 없이 기존 사실과 미실행 상태 보존 |
| 도메인 정책 이력 | 기존 도메인 정책 변경 | 기존 문서 위치를 우선하고 변경 전후 내용·근거·상태 기록 |

## 결과 기록

- 시나리오별로 아래 항목을 기록
  1. 실행 날짜와 평가 대상 하네스 버전 또는 커밋
  2. 테스트 저장소의 기준 커밋과 재현 조건
  3. 요청 내용과 실제 Agent 행동
  4. 실행 명령, 결과, 확인 가능한 로그나 diff
  5. 판정(통과/실패/미실행)과 기대 행동과의 차이
- 문서 검토만 진행한 경우 실행 판정은 미실행으로 기록
- 관련 시나리오가 모두 통과한 경우에만 해당 범위의 실행 검증 완료로 보고
- 실패 항목은 규칙이나 실행 환경을 수정한 뒤 다시 검증
