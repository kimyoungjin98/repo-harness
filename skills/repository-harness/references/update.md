# 원본 경로와 갱신 기준

## 기존 설치 찾기

- 대상 `AGENTS.md`의 하네스 연결 블록에서 `project.md` 위치를 먼저 확인. 연결이 없으면 기본 위치인 `docs/harness/project.md` 확인
- 명시적인 외부 원본 지정이 있으면 `external` 모드로 사용. 사용자가 기본 포함 규칙 사용을 요청하면 `bundled` 모드로 전환
- 지정이 없고 기존 설정의 `source_mode`가 `external`이면 `project.md`의 경로와 상태 파일의 `source_dir`를 확인. 명시적으로 선택한 외부 원본이 없으면 다른 원본으로 바꾸지 말고 필요한 경로만 확인
- `source_mode`가 `bundled`이거나 최초 구성이면 현재 실행 중인 스킬의 `references/rules/` 사용. 이전 설치의 절대 경로가 남아 있어도 최신 스킬의 포함 규칙을 사용
- 구형 상태에 `source_mode`가 없고 원본 경로만 있으면 기존 외부 원본 선택을 유지. 기록된 경로가 현재 스킬의 포함 규칙 경로이면 `bundled`로 기록
- 저장소 루트를 지정한 경우 그 아래 `docs/`를 확인. 구형 배치는 루트에 `main.md` 등이 있으면 사용 가능
- 원본에 `main.md`, `code-base.md`, `test.md`, `git-branch.md`, `evaluation.md`, `code-base/`가 모두 있는지 확인
- 포함 규칙 모드는 `manifest.json`의 `bundled_sha256`과 실제 문서 해시를 확인. 불일치하면 재설치가 필요하며 대상 문서는 보존
- 성공한 원본 경로는 실제 절대 경로로 `project.md`와 상태 파일에 기록. 경로를 찾았다는 사실만으로 설치 버전을 갱신하지 않음

## 최초 구성 시 보존할 정보

- 설치 문서 폴더 아래 `.harness-state/`에 `state.json`과 `baseline/`을 생성
- `state.json`에는 아래 정보를 기록
  - `schema_version`: `1`
  - `source_mode`: `bundled` 또는 `external`
  - `source_dir`: 확인한 규칙 원본 디렉터리. 포함 규칙 모드에서는 기록용이며 다음 실행은 현재 스킬 위치 기준
  - `source_files`: 사용한 원본 파일의 상대 경로와 SHA-256
  - `baseline_files`: 생성한 문서의 상대 경로와 기준 사본의 SHA-256
  - `agents_block_sha256`: 최초 생성한 하네스 연결 블록의 SHA-256
- `baseline/`에는 생성한 운영 문서와 `project.md`를 설치 문서 폴더 기준의 상대 경로로 저장
- `agents-block.md`에는 Agent가 생성한 하네스 연결 블록만 저장. 기존 `AGENTS.md` 전체를 관리 대상으로 가져오지 않음
- 기준 사본은 이후 사용자 변경을 구분하기 위한 설치 기록이며, 사용자가 편집하는 기획 원본이 아님. 운영 문서에서 기준 사본으로 링크하지 않음
- 최초 구성 전 이미 존재하는 문서는 사용자 문서로 취급. 기존 내용을 생성 결과로 간주하여 기준 사본으로 등록하거나 덮어쓰지 말고, 병합 범위가 명확하지 않은 부분만 확인

## 갱신

- 기준 사본과 상태 파일의 해시를 확인한 뒤 갱신 시작. 사본이 없거나 손상되었으면 기존 문서를 사용자 문서로 보존하고, 변경 제안과 확인이 필요한 부분을 보고
- 이전 생성 내용(B), 현재 설치 내용(L), 새 원본을 현재 프로젝트에 맞게 적용한 생성 후보(R)를 비교
- R을 만들 때 프로젝트의 기존 기술과 명시적 예외는 유지하되, L의 수동 수정 전체를 R에 먼저 복사하지 않음
- 원본과 프로젝트 설정이 바뀌지 않았다면 기존 생성 기준을 재사용. 날짜나 표현만 바꾸기 위한 재생성은 하지 않음

| 비교 결과 | 처리 |
| --- | --- |
| L과 B가 같음 | R 적용 |
| R과 B가 같음 | L 유지 |
| L과 R이 같음 | 해당 내용 유지 |
| 서로 다른 부분이 변경됨 | 두 변경을 함께 반영 |
| 같은 규칙의 의미가 서로 다르게 변경됨 | 충돌로 기록하고 해당 부분의 선택만 확인 |

- 줄 위치뿐 아니라 규칙의 의미를 비교. 서로 다른 줄이어도 상충하는 정책이면 충돌로 처리
- 원본에서 삭제된 문서나 규칙은 L에 사용자 변경이 없는 경우에만 삭제 반영
- 사용자가 삭제한 관리 문서도 사용자 변경으로 취급. 동일 부분에 원본 변경이 없다면 삭제 유지
- 관리 목록에 없는 기존 파일과 연결 블록 밖의 내용은 보존
- 연결 블록에도 B/L/R 기준 적용. 블록의 중복이나 경계 손상이 있으면 자동 교체하지 않음
- 충돌이 남아 있으면 설치 파일과 상태를 갱신하지 않고, 임시 위치에 만든 후보와 차이를 바탕으로 필요한 결정만 질문
- 충돌이 해소되면 병합 결과의 링크, 명령 근거, 사용자 변경 보존 여부를 확인한 뒤 적용
- 검증이 끝난 뒤 기준 사본은 병합 결과가 아닌 R로 갱신. 그래야 L에서 유지한 사용자 수정이 다음 실행에서도 구분됨
- 상태 파일과 기준 사본은 문서 적용이 성공한 뒤 함께 갱신. 쓰기 실패 시 이전 설치 상태로 복구하고 실패 지점을 보고
- 갱신 완료 시 반영한 원본 변경, 유지한 사용자 변경, 검증 결과를 구분하여 보고
