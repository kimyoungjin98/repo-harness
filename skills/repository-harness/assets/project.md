# 프로젝트 하네스 설정

## 적용 정보

- 구성 날짜 : 분석 결과로 작성
- 규칙 원본 모드 : `bundled`(스킬에 포함된 규칙) 또는 `external`(사용자 지정 원본)
- 규칙 원본 경로 : 확인한 원본 문서 디렉터리의 실제 절대 경로
- 하네스 원본과 버전 : 원본 위치와 커밋 또는 문서 해시
- 갱신 기준 : 설치 문서 폴더의 `.harness-state/state.json`과 기준 사본 사용
- 적용 범위 : 프론트엔드 / 백엔드 / 모노레포 / 구조 미정 중 해당 범위
- 규칙 우선순위 : 사용자 요청 → 기존 프로젝트 규칙 → 프로젝트 override → 공통 하네스 규칙. 베이스의 기술 지정은 신규 구성 기본값

## 프로젝트 override

- override 문서와 적용 범위 : 실제 파일 링크와 적용 범위를 기록. 없으면 없음
- 현재 작업에 해당하는 override를 공통 규칙과 함께 읽고 우선 적용
- 대체·비적용된 공통 항목은 함께 적용하지 않고, 지정하지 않은 부분은 공통 규칙을 적용

| --- | --- | --- | --- |
| 분석한 영역으로 작성 | 실제 경로 | 기존 기술 | 근거 경로 |

## 준비 상태

| 준비물 | 필요한 시점 | 확인 상태 | 다음 조치 |
| --- | --- | --- | --- |
| AI Agent CLI와 계정 | 구성 및 작업 실행 | 준비 / 미준비 / 미확인 | 확인 결과로 작성 |
| Node.js와 npm/npx | Skills CLI 설치·갱신 | 준비 / 미준비 / 미확인 | 확인 결과로 작성 |
| Git CLI와 원격 인증 | 저장소 다운로드·브랜치·push | 준비 / 미준비 / 미확인 | 로컬 도구와 원격 인증을 구분 |
| 호스팅 서비스 CLI/API 인증 | PR 생성 | 준비 / 미준비 / 미확인 | 확인 결과로 작성 |
| Discord 또는 Slack Webhook | 알림 전송 | 준비 / 미준비 / 미확인 / 비적용 | 설정 이름과 전송 권한만 기록 |

- 준비 상태는 확인 가능한 정보로 기록하고, 확인하지 못한 인증이나 연동은 미확인으로 표시
- 인증정보와 Webhook URL 원문은 기록하지 않음
- Python 3는 베이스의 배포용 규칙 생성에만 필요하므로 대상 프로젝트의 필수 준비물로 추가하지 않음

## 검증 명령

| 영역 | 검사 | 실행 위치 | 명령 | 설정 근거 | 구성 시 실행 결과 |
| --- | --- | --- | --- | --- | --- |
| 분석한 영역으로 작성 | lint / 타입 / 테스트 / 빌드 등 | 실제 경로 | 실제 명령 또는 미구축 | 근거 경로 | 통과 / 실패 / 미실행 및 사유 |

- 해당하지 않는 검사는 비적용 사유를 기록
- 명령이 확인되었다는 사실과 실제 실행 통과를 구분
- DB 검증은 격리된 환경에서 진행하고 접속정보는 이 문서에 기록하지 않음

## 브랜치와 PR

- 브랜치 전략과 확인 근거 : 분석 결과로 작성
- 기준 브랜치 : 실제 브랜치 또는 미확정
- PR 대상과 사용 도구 : 확인된 설정 또는 미구축
- merge 및 배포 : PR 생성과 별도 권한으로 처리

## 문서와 후속 작업

- 작업 이력 위치 : 기존 경로 우선, 없으면 `docs/history/YYYY-MM-DD.md`
- 도메인 정책 위치 : 기존 경로 우선, 없으면 `docs/plan/[도메인명].md` (관련 정책 변경 시 작성)
- 문서 작성 규격 : 설치된 `document-write.md` 참조
- merge 이후 자동화 : 기존 실행 주체와 조건 또는 미구축
- 알림 연동 : 기존 연동과 권한 또는 미구축. 인증정보는 기록하지 않음

## 예외와 미확정 항목

- 기존 규칙을 유지하여 적용하지 않은 기본값과 사유를 기록
- 비적용 영역과 사유를 기록
- 확인이 필요한 항목은 확인 시점과 함께 기록. 없는 경우 없음으로 작성
