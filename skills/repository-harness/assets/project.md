# 프로젝트 하네스 설정

## 적용 정보

- 구성 날짜 : 분석 결과로 작성
- 규칙 원본 모드 : `bundled`(스킬에 포함된 규칙) 또는 `external`(사용자 지정 원본)
- 규칙 원본 경로 : 확인한 원본 문서 디렉터리의 실제 절대 경로
- 하네스 원본과 버전 : 원본 위치와 커밋 또는 문서 해시
- 갱신 기준 : 설치 문서 폴더의 `.harness-state/state.json`과 기준 사본 사용
- 적용 범위 : 프론트엔드 / 백엔드 / 모노레포 / 구조 미정 중 해당 범위
- 규칙 우선순위 : 사용자 요청과 기존 프로젝트 규칙 우선, 베이스의 기술 지정은 신규 구성 기본값

## 구조와 기술

| 영역 | 경로 | 사용 기술 | 확인한 설정 파일 |
| --- | --- | --- | --- |
| 분석한 영역으로 작성 | 실제 경로 | 기존 기술 | 근거 경로 |

## 검증 명령

| 영역 | 검사 | 실행 위치 | 명령 | 설정 근거 | 구성 시 실행 결과 |
| --- | --- | --- | --- | --- | --- |
| 분석한 영역으로 작성 | lint / 타입 / 테스트 / 빌드 등 | 실제 경로 | 실제 명령 또는 미구축 | 근거 경로 | 통과 / 실패 / 미실행 및 사유 |

- 해당하지 않는 검사는 비적용 사유를 기록
- 명령이 확인되었다는 사실과 실제 실행 통과를 구분
- DB 검증은 격리된 환경에서 진행하고 접속정보는 이 문서에 기록하지 않음

## 브랜치와 PR

- 브랜치 전략과 확인 근거 : 분석 결과로 작성
- 기준 브랜치 : 실제 브랜치 또는 미확정
- PR 대상과 사용 도구 : 확인된 설정 또는 미구축
- merge 및 배포 : PR 생성과 별도 권한으로 처리

## 문서와 후속 작업

- 작업 이력 위치 : 기존 경로 또는 미구축
- 도메인 정책 위치 : 기존 경로 또는 미구축
- merge 이후 자동화 : 기존 실행 주체와 조건 또는 미구축
- 알림 연동 : 기존 연동과 권한 또는 미구축. 인증정보는 기록하지 않음

## 예외와 미확정 항목

- 기존 규칙을 유지하여 적용하지 않은 기본값과 사유를 기록
- 비적용 영역과 사유를 기록
- 확인이 필요한 항목은 확인 시점과 함께 기록. 없는 경우 없음으로 작성
